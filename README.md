# 1. Как числа хранятся в памяти ЭВМ

## Теория

### Зачем это знать

Компьютер не умеет хранить «любое» число. Память конечна, поэтому чисел, которые он может представить, **конечное количество**, и расположены они **с «шагом»**. Всё, что не попало ровно в это множество, округляется. Именно отсюда и появляются первые погрешности.

### Простая модель: 8-разрядный калькулятор (фиксированная запятая)

Один разряд идёт под знак, 8 разрядов под цифры, запятая может стоять где угодно.

- **Диапазон:** от `−99 999 999` до `99 999 999`, то есть `[−(10⁸ − 1); 10⁸ − 1]`. Если результат выходит за него, калькулятор показывает **переполнение**.
- **Машинный нуль:** всё, что лежит строго между `−10⁻⁷` и `10⁻⁷` (сами концы не входят), калькулятор показывает как `0`.
- **Шаг:** чем больше цифр в целой части, тем меньше остаётся на дробную.
   - 7 цифр в целой части → шаг `0,1`
   - 6 цифр → шаг `0,01`
   - …
   - 1 цифра → шаг `10⁻⁷`

Получается своего рода «лесенка»: шаг разный на разных участках, а числа между ступеньками округляются.

### Экспоненциальная форма (плавающая запятая)

```
M · 10^P
```

`M` — **мантисса**, `P` — **порядок**. Мантисса обычно либо из промежутка `(0; 1)` с ненулевой цифрой в разряде десятых (`0,345 · 10⁻³`), либо с одной ненулевой цифрой в целой части (`3,45 · 10⁻⁴`). Диапазон растёт, но конечность и дискретность множества чисел никуда не деваются. Меняется только шаг на разных участках.

### Как это устроено в компьютере (стандарт IEEE 754)

Принцип тот же, только используется двоичная система. Число хранится в трёх частях:

```
| S (знак) | E (смещённый порядок) | M (дробная часть мантиссы) |
```

**Алгоритм записи числа (на примере 147,375):**

1. **Перевести в двоичную.** `147,375 = 10010011,011₂`
2. **Нормализовать:** запятая после первой единицы. `1,0010011011 · 2⁷`
3. **Порядок смещаем**, чтобы не хранить его знак: прибавляем смещение. Для `single` это `127`, поэтому `E = 7 + 127 = 134 = 10000110₂`.
4. **Целую «1» мантиссы не записываем**, она всегда равна 1 (скрытый бит). Записываем только дробную часть, дополняя нулями до нужной длины: `00100110110000000000000`.
5. **Знак:** `S = 0` для `+`, `S = 1` для `−`.

В итоге для `147,375` (single, 32 бита) получаем:

```
0 | 10000110 | 00100110110000000000000
```

**Обратное восстановление:**

```
F = (−1)^S · 2^(E − смещение) · (1 + M / 2^m)
```

Здесь `m` — число бит дробной части мантиссы, смещение = `2^(p−1) − 1`, а `p` — число бит порядка.

### Типы чисел

| Тип      | Байт | Формат (знак / порядок / мантисса) | Смещение | Значащих десятичных цифр |
| -------- | ---- | ---------------------------------- | -------- | ------------------------ |
| Single   | 4    | 1 / 8 / 23                         | 127      | 7–8                      |
| Real     | 6    | —                                  | —        | 11–12                    |
| Double   | 8    | 1 / 11 / 52                        | 1023     | 15–16                    |
| Extended | 10   | —                                  | —        | 19–20                    |

### Главное

Многие десятичные дроби (например, `0,1`) в двоичной системе **бесконечные**, как `1/3` в десятичной. Поэтому компьютер хранит их только **приближённо**.

### Короткая памятка по переводу

- **Целая часть:** делим на 2 и выписываем остатки снизу вверх.
- **Дробная часть:** умножаем на 2; целая часть результата — очередная двоичная цифра, дробную часть умножаем дальше.

8 цифр, наибольшее число из девяти девяток: `99 999 999 = 10⁸ − 1`. Отрицательные симметричны.

**Ответ:** `[−99 999 999; 99 999 999]`. За пределами этого отрезка калькулятор сообщит о переполнении.

</details>

**Задание 1.2** 🟢 Что покажет 8-разрядный калькулятор для чисел `0,00000007` и `0,0000001`? Что будет при `99 999 999 + 1`?

<details>
<summary>Ответ и решение 1.2</summary>

Машинный нуль — это промежуток `(−10⁻⁷; 10⁻⁷)`, **концы не входят**.

- `0,00000007 = 7·10⁻⁸` лежит внутри промежутка → показано как **0**.
- `0,0000001 = 10⁻⁷` — это конец, он не входит в машинный нуль → число **отображается** как `0,0000001`.
- `99 999 999 + 1 = 100 000 000 = 10⁸` выходит за диапазон → **переполнение**.

</details>

**Задание 1.3** 🟢 Чему равен шаг между соседними числами в 8-разрядном калькуляторе, если в целой части 3 цифры? А если 7 цифр?

<details>
<summary>Ответ и решение 1.3</summary>

На дробную часть остаётся `8 − (число цифр целой части)` разрядов.

- 3 цифры в целой части → 5 знаков после запятой → шаг `10⁻⁵ = 0,00001`.
- 7 цифр в целой части → 1 знак после запятой → шаг `0,1`.

**Ответ:** `0,00001` и `0,1`.

</details>

<details>
<summary>Ответ и решение 1.4</summary>

Двигаем запятую так, чтобы сразу после неё стояла ненулевая цифра, и считаем, на сколько разрядов сдвинули.

- а) `0,000345 = 0,345 · 10⁻³` (сдвиг на 3 вправо → порядок −3)
- б) `456 000 = 0,456 · 10⁶` (сдвиг на 6 влево → порядок +6)
- в) `−72,5 = −0,725 · 10²`

</details>

**Задание 1.11** 🟡 Восстановите десятичное число по битам Single:

б) `1 | 10000000 | 11000000000000000000000`

- а) `S = 0`; `E = 10000011₂ = 131` → порядок `131 − 127 = 4`. Мантисса `1,01₂ = 1 + 0,25 = 1,25`. `F = 1,25 · 2⁴ = 1,25 · 16 = 20`. **Ответ: 20**.

**Задание 1.14** 🔴 Число `0,1` в Single. Постройте его двоичную запись и объясните, почему в компьютере `0,1 + 0,2 ≠ 0,3`.

<details>
<summary>Ответ и решение 1.14</summary>

**Шаг 1. Переводим `0,1` в двоичную систему** (умножаем на 2):

```
0,1·2 = 0,2 → 0
0,2·2 = 0,4 → 0
0,4·2 = 0,8 → 0
0,8·2 = 1,6 → 1
0,6·2 = 1,2 → 1
0,2·2 = 0,4 → 0   ← дальше цикл повторяется
0,4·2 = 0,8 → 0
0,8·2 = 1,6 → 1
...
```

`0,1 = 0,000110011001100…₂` — бесконечная периодическая дробь (период `1100`).

**Шаг 2. Нормализуем:** `1,10011001100…₂ · 2⁻⁴`. Порядок `E = −4 + 127 = 123 = 01111011₂`.

**Шаг 3. Мантисса:** берём 23 бита `10011001100110011001100`, а следующие за ними биты `1100…` начинаются с 1 и продолжаются, то есть остаток больше половины шага. Поэтому последний бит округляется вверх: `10011001100110011001101`.

**Ответ:**

```
0 | 01111011 | 10011001100110011001101
```

**Шаг 4. Что реально хранится:** обратный перевод даёт `0,100000001490116…`, а не ровно `0,1`. Появилась погрешность округления порядка `10⁻⁹`.

**Шаг 5. Почему `0,1 + 0,2 ≠ 0,3`:** и `0,1`, и `0,2`, и `0,3` хранятся с небольшими ошибками разных знаков и величин. Их сумма (даже в Double) получается `0,30000000000000004`, что не равно ближайшему к `0,3` числу в памяти. Вывод: **вещественные числа нельзя сравнивать на строгое равенство**, сравнивать нужно с допуском: `|a − b| < eps`.

</details>

**Задание 1.16** 🔴 _(на размышление)_ Мантисса Single содержит 23 бита плюс скрытая единица. Какое наибольшее `N` такое, что **все** целые числа от `0` до `N` в Single хранятся точно? Почему `16 777 217` уже не получится?

<details>
<summary>Ответ и решение 1.16</summary>

С учётом скрытой единицы у нас **24 значащих двоичных разряда**. Все целые числа до `2²⁴ = 16 777 216` помещаются в 24 бита и записываются точно.

Число `16 777 217 = 2²⁴ + 1` в двоичной записи имеет 25 значащих разрядов (`1` + 23 нуля + `1` после ещё одного нуля), а у нас всего 24, поэтому последняя единица теряется. На уровне `2²⁴` шаг между соседними числами уже равен `2`, и нечётные числа выпадают.

**Ответ:** `N = 16 777 216`. Следствие: счётчик в `float` после этого значения перестанет увеличиваться на 1.

</details>

# 2. Приближённые значения и погрешности

## Теория

### Откуда вообще берутся погрешности

1. **Модель** — любая математическая модель — это упрощение реальности.
2. **Метод** — точное решение часто требует бесконечного числа операций, а мы обрываем их на конечном шаге.
3. **Исходные данные** — получены измерениями, а точных приборов не бывает.
4. **Вычисления** — числа в компьютере округляются (см. тему 1).

Поэтому вместо точных величин мы работаем с **приближёнными значениями** и должны понимать, насколько они могут ошибаться.

### Абсолютная погрешность

Пусть `a` — точное значение, `x` — приближённое.

```
ε = |a − x|
```

**Пример.** Файл весит 93 696 байт, а в окне папки написано «92 КБ». Тогда `x = 92·1024 = 94 208`, а `ε = |93 696 − 94 208| = 512 байт`.

### Граница абсолютной погрешности

Чаще всего точное `a` неизвестно (например, если измеряем стол линейкой), поэтому настоящее `ε` найти нельзя. Но можно указать число `Δx`, **больше которого погрешность быть не может**:

```
|a − x| ≤ Δx
```

Обычно `Δx` берут из практических соображений (цена деления прибора). Это неравенство равносильно двойному:

```
x − Δx ≤ a ≤ x + Δx
```

Числа `x − Δx` и `x + Δx` — нижняя и верхняя границы приближения. Короткая запись: `a = x ± Δx`.

### Относительная погрешность

Абсолютная погрешность **не показывает качество измерения**: ошибка 1 см на длине 100 см — это плохо, а ошибка 1 км на 800 км — отлично. Поэтому сравнивают погрешность с размером величины.

```
δx = Δx / |x|             (в долях)
δx = Δx / |x| · 100%      (в процентах)
```

Обратный переход:

```
Δx = |x| · δx
Δx = |x| · (δx в %) / 100%
```

**Правило сравнения точности:** чем **меньше относительная** погрешность, тем точнее измерение. Абсолютные погрешности сравнивать можно только у величин одной природы и одного масштаба.

# 3. Запись приближённых чисел: верные цифры и округление

## Теория

### Значащие цифры

**Значащие цифры** — все цифры числа, начиная с первой слева **ненулевой**.

- `0,04021` → 4 значащие цифры (4, 0, 2, 1)
- `4,02100` → 6 значащих цифр (нули справа считаются, они что-то говорят о точности)

### Верные и сомнительные цифры

Цифра в записи приближённого числа **верна**, если погрешность достаточно мала по сравнению с её разрядом. Есть два уровня строгости:

| Смысл                | Условие для цифры в некотором разряде |
| -------------------- | ------------------------------------- |
| **В широком смысле** | `Δx ≤ 1 единицы этого разряда`        |
| **В строгом смысле** | `Δx ≤ ½ единицы этого разряда`        |

Остальные цифры (правее последней верной) — **сомнительные**. Количество верных цифр в строгом смысле либо такое же, как в широком, либо на 1 меньше.

**Пример:** `47,3825 ± 0,003`

| Цифра | Единица разряда | Δx = 0,003 ≤ единицы? | Вывод        |
| ----- | --------------- | --------------------- | ------------ |
| 4     | 10              | да                    | верная       |
| 7     | 1               | да                    | верная       |
| 3     | 0,1             | да                    | верная       |
| 8     | 0,01            | да                    | верная       |
| 2     | 0,001           | нет (0,003 > 0,001)   | сомнительная |
| 5     | 0,0001          | нет                   | сомнительная |

Для строгого смысла: разряд сотых, ½ единицы = `0,005 ≥ 0,003` ✓ → цифра 8 верна и в строгом смысле.

### Как быстро найти последнюю верную цифру (широкий смысл)

1. Если `Δx` записана **одной единицей** с нулями (`0,001`, `0,1`, `100`), то эта единица стоит в разряде последней верной цифры.
2. Иначе ищем **ближайшее большее** число вида «одна единица и нули» (`0,003 → 0,01`; `0,02 → 0,1`; `4 → 10`). Положение его единицы и есть разряд последней верной цифры.

Для **строгого смысла** после этого проверяем `Δx ≤ ½ единицы`. Если нет, сдвигаемся на разряд влево.

### Правила округления

Когда отбрасываем сомнительные цифры:

- Первая отбрасываемая цифра **меньше 5** → последняя оставшаяся **не меняется**.
- Первая отбрасываемая цифра **больше 5**, либо равна 5 и за ней есть ещё цифры → последняя оставшаяся **увеличивается на 1**.
- Отбрасывается **ровно одна цифра 5** → последняя оставшаяся **чётная сохраняется, нечётная увеличивается на 1** (правило «к чётному»).

Примеры (до десятых): `4,25 → 4,2`; `4,35 → 4,4`; `4,351 → 4,4`; `4,349 → 4,3`.

### Если погрешность не указана

Когда число записано «всеми верными цифрами», погрешность считается:

- в **широком** смысле: `Δx = 1 единица последнего разряда`;
- в **строгом** смысле: `Δx = ½ единицы последнего разряда`.

Например, `3,45` (все цифры верны в строгом смысле) → `Δx = 0,005`.

**Почему не больше:** условие строгого смысла (`Δx ≤ ½ единицы`) жёстче условия широкого (`Δx ≤ 1 единицы`). Всё, что верно в строгом смысле, верно и в широком, поэтому строгих цифр не больше. Если цифра прошла в широком, но не прошла в строгом, она единственная, и теряется ровно одна (следующая левее уже проходит, потому что единица её разряда в 10 раз больше).

# 4. Погрешности арифметических действий

## Теория

Пусть даны два приближённых числа: `a = x ± Δx`, `b = y ± Δy`. Что будет с погрешностью результата?

### Как это получается

Записываем `x − Δx ≤ a ≤ x + Δx` и `y − Δy ≤ b ≤ y + Δy`. Складываем / вычитаем / умножаем неравенства и смотрим, насколько результат может «уплыть». В произведении малое слагаемое `Δx·Δy` отбрасывается (оно намного меньше остальных).

### Формулы в одном месте

| Операция | Абсолютная погрешность `Δ`   | Относительная погрешность `δ`       |
| -------- | ---------------------------- | ----------------------------------- |
| `x + y`  | `Δx + Δy`                    | `(\|x\|·δx + \|y\|·δy) / \|x + y\|` |
| `x − y`  | `Δx + Δy`                    | `(\|x\|·δx + \|y\|·δy) / \|x − y\|` |
| `x · y`  | `\|y\|·Δx + \|x\|·Δy`        | `δx + δy`                           |
| `x / y`  | `(\|y\|·Δx + \|x\|·Δy) / y²` | `δx + δy`                           |

### Что здесь важно запомнить

1. **Сложение и вычитание:** абсолютные погрешности **складываются** (даже при вычитании!).
2. **Умножение и деление:** **относительные** погрешности складываются.
3. **Ловушка вычитания:** если `x ≈ y`, то разность `x − y` маленькая, а `Δx + Δy` — нет. Относительная погрешность разности **резко растёт**. Поэтому пособие советует избегать вычитания близких чисел.
4. **Деление на малое число** тоже усиливает погрешность.
5. Сумму нескольких чисел удобнее складывать **в порядке возрастания** их модулей.

### Как решать такие задачи

1. Сначала найди результат операции.
2. Затем найди `Δ` по таблице.
3. Если нужно, найди `δ = Δ / |результат|`. Для `×` и `÷` удобнее сразу взять `δ = δx + δy`, а потом найти `Δ = |результат| · δ`.
4. В конце запиши границы: `результат ± Δ`.

# 5. Погрешность функции приближённого аргумента

## Теория

### Что нужно найти

Известно `a = x ± Δx`. Нужно вычислить `f(a)` и понять, насколько ошибётся результат, если мы подставим приближённое `x`.

### Как это работает

Погрешность аргумента — это **приращение аргумента**. Приращение функции почти равно её **дифференциалу** (производная × приращение аргумента). Значит:

```
Δf(x) = |f′(x)| · Δx                        (абсолютная)

δf(x) = |x · f′(x) / f(x)| · δx             (относительная)
```

**Смысл:** производная — это «коэффициент усиления» ошибки. Большая производная → функция крутая → маленькая ошибка аргумента превращается в большую ошибку результата.

### Таблица для элементарных функций

| `f(x)`                  | Абсолютная погрешность `Δf`               | Относительная погрешность `δf`        |
| ----------------------- | ----------------------------------------- | ------------------------------------- |
| `xⁿ`                    | `n·\|x\|ⁿ⁻¹·Δx`                           | `n·δx`                                |
| `√x`                    | `Δx / (2√x)`                              | `½·δx`                                |
| `1/x`                   | `Δx / x²`                                 | `δx`                                  |
| `eˣ`                    | `eˣ·Δx`                                   | `\|x\|·δx`                            |
| `aˣ`                    | `aˣ·ln a·Δx`                              | `\|x\|·ln a·δx`                       |
| `ln x`                  | `Δx / \|x\|`                              | `δx / \|ln x\|`                       |
| `lg x`                  | `Δx / (\|x\|·ln 10)`                      | `δx / \|ln x\|`                       |
| `sin x`                 | `\|cos x\|·Δx`                            | `\|x·ctg x\|·δx`                      |
| `cos x`                 | `\|sin x\|·Δx`                            | `\|x·tg x\|·δx`                       |
| `tg x`                  | `Δx / cos²x`                              | `2\|x\| / \|sin 2x\| · δx`            |
| `ctg x`                 | `Δx / sin²x`                              | `2\|x\| / \|sin 2x\| · δx`            |
| `arcsin x`              | `Δx / √(1−x²)`                            | `\|x\| / (\|arcsin x\|·√(1−x²)) · δx` |
| `arccos x`              | `Δx / √(1−x²)`                            | `\|x\| / (\|arccos x\|·√(1−x²)) · δx` |
| `arctg x`               | `Δx / (1+x²)`                             | `\|x\| / (\|arctg x\|·(1+x²)) · δx`   |
| `arcctg x`              | `Δx / (1+x²)`                             | `\|x\| / (\|arcctg x\|·(1+x²)) · δx`  |
| `xʸ` (оба приближённые) | `xʸ · (\|y\|/\|x\| · Δx + \|ln x\| · Δy)` | `\|y·ln x\|·δy + \|y\|·δx`            |

### Что здесь важно запомнить

- Степень `n` **умножает** относительную погрешность на `n`: `δ(x²) = 2δx`, `δ(x³) = 3δx`.
- Корень **уменьшает** относительную погрешность вдвое.
- `1/x` её не меняет.
- `eˣ` опасна при больших `x`: `δ = |x|·δx`.
- Около точек, где производная «взрывается» (например, `tg x` при `x → π/2`), погрешность растёт катастрофически.
- Аргумент тригонометрических функций всегда в **радианах**.

# 6. Выполнение приближённых вычислений

## Теория

Есть два способа вычислить выражение с приближёнными числами. Первый точнее, второй быстрее.

### Способ А. Считаем погрешность каждой операции

Для сложного выражения разбиваем его на элементарные действия и по порядку ведём **таблицу**. Правила:

1. Считаем значение действия на калькуляторе (с запасом знаков).
2. Находим абсолютную погрешность `Δ` действия по формулам тем 4 и 5.
3. Записываем `Δ` **не более чем с двумя значащими цифрами**, округляя **с избытком** (любое отбрасывание → последняя цифра `+1`). Так мы не завышаем точность.
4. Сравниваем `Δ` с единицей (или половиной единицы) разряда, чтобы понять, сколько цифр результата верны.
5. Результат округляем, оставляя **одну запасную цифру** сверх верных.
6. Эта операция округления вносит **погрешность округления** `|точное − округлённое|`. Её **прибавляем к `Δ`** действия.
7. Дальше работаем уже с округлёнными значениями.
8. В конце округляем до последней верной цифры.

Исходные числа, записанные «всеми верными цифрами в строгом смысле», имеют `Δ = ½ единицы последнего разряда`.

### Способ Б. Считаем верные цифры (быстрая оценка)

Погрешности не считаем, только следим за числом верных цифр:

1. **Сложение / вычитание.** Находим разряд последней верной цифры у каждого слагаемого. **Самый старший** из этих разрядов даёт разряд последней верной цифры результата. Остальные слагаемые перед сложением округляем до разряда на один младше.
2. **Умножение / деление.** Берём число с **наименьшим количеством значащих цифр** (допустим, `k`). Остальные округляем до `k + 1` значащих цифр. В результате верны `k` значащих цифр.
3. **Функция.** Смотрим на `|f′(x)|`:
   - если `|f′| ≤ 1` (или около того): значение имеет **столько же** верных десятичных знаков, сколько аргумент;
   - если `|f′| > 1`: находим **наименьшее `k`**, при котором `|f′| ≤ 10ᵏ`. Верных десятичных знаков **на `k` меньше**, чем в аргументе.
4. В записи результата оставляем **одну запасную цифру**, в окончательном ответе её округляем.

Рекомендации: избегать вычитания близких чисел и деления на малые; складывать в порядке возрастания модулей.

### Пример из пособия

Вычислить `A = (a² + √b) / (eᵇ · ln(1 + b²))` при `a = 0,963`, `b = 2,436` (все цифры верны в строгом смысле, т. е. `Δa = Δb = 0,0005`).

| Действие       | `a²`   | `√b`    | `a² + √b` | `eᵇ`   | `1+b²` | `ln(1+b²)` | `eᵇ·ln(…)` | `A`     |
| -------------- | ------ | ------- | --------- | ------ | ------ | ---------- | ---------- | ------- |
| Результат      | 0,927  | 1,5608  | 2,488     | 11,43  | 6,934  | 1,936      | 22,13      | 0,1124  |
| `Δ` (способ А) | 0,0014 | 0,00021 | 0,0019    | 0,0085 | 0,0025 | 0,00040    | 0,025      | 0,00025 |

**Итог:** `A = 0,112 ± 0,0003`. Способ Б даёт тот же `0,112`: совпадение хорошее.

**`b²`.** `1,35² = 1,8225`. `Δ = 2·1,35·0,005 = 0,0135`. Строгий смысл: `≤ 0,05` ✓, `≤ 0,005` ✗ → верен 1 десятичный знак. Запасной → `1,82`. Округление: `0,0025`. Полная `Δ = 0,0135 + 0,0025 = 0,016`.

**Сумма.** `1,008 + 1,82 = 2,828`. `Δ = 0,0019 + 0,016 = 0,0179` → **0,018**. Строгий смысл: `0,018 ≤ 0,05` ✓ (десятые).

**Ответ:** `D = 2,828 ± 0,018`, верными цифрами **D ≈ 2,8**. Основную погрешность вносит `b²`.

# Шпаргалка по формулам

**Погрешности**

```
ε = |a − x|              Δx: ε ≤ Δx            a = x ± Δx
δx = Δx / |x|            Δx = |x| · δx          (в % делим/умножаем на 100)
```

**Верные цифры**

```
широкий смысл: Δx ≤ 1 единицы разряда
строгий смысл: Δx ≤ ½ единицы разряда
нет погрешности: широкий → Δx = 1 ед. разряда; строгий → Δx = ½ ед. разряда
```

**Округление:** `<5` — не меняем; `>5` или `5` с продолжением — `+1`; одна `5` — к чётному.

**Арифметика**

| Операция | Δ                          | δ               |
| -------- | -------------------------- | --------------- |
| `x ± y`  | `Δx + Δy`                  | `Δ / \|x ± y\|` |
| `x · y`  | `\|y\|Δx + \|x\|Δy`        | `δx + δy`       |
| `x / y`  | `(\|y\|Δx + \|x\|Δy) / y²` | `δx + δy`       |

**Функция**

```
Δf = |f′(x)| · Δx
δf = |x · f′(x) / f(x)| · δx
δ(xⁿ) = n·δx      δ(√x) = ½·δx      δ(1/x) = δx      δ(eˣ) = |x|·δx
```

**IEEE 754**

```
F = (−1)^S · 2^(E − (2^(p−1) − 1)) · (1 + M / 2^m)
Single: 1 / 8 / 23, смещение 127        Double: 1 / 11 / 52, смещение 1023
```

**Практические правила**

- Избегай вычитания близких чисел и деления на малые.
- Суммируй в порядке возрастания модулей.
- Погрешность записывай ≤ 2 значащими цифрами **с избытком**; результат округляй с одной запасной цифрой.
- Вещественные числа в программах сравнивай с допуском, а не через `==`.
